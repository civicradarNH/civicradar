# CivicRadar bug audit — 2026-07-26

**Scope:** Static PWA (`index.html`, `js/*`, `css/styles.css`, `sw.js`, wards, legal HTML, `supabase/schema.sql`, tests as intent). Android TWA: light touch (`assetlinks.json` present).  
**Method:** Static read/grep of critical paths at **v453**. No application code changed.  
**Confidence:** **Confirmed** = code proves the defect. **Suspected** = needs device/repro.

---

## 1. Executive summary

CivicRadar’s recent fix wave (GPS permission UX, claim-code offline copy, society/ward tagging, sheet `autoPan`, celebration double-fire, self-resolve points) looks **largely landed and clean**. The highest remaining risks are **sync integrity on optimistic mutations** (local UI wins, cloud silently fails, next `pullAll` reverts status while points stick) and **stored XSS via unescaped `src` attributes** for report images that pass a weak `data:image/` allowlist.

Severity mix: **2× P0**, **3× P1**, several **P2**. Overall posture for a civic PWA: solid hardening on RLS/column grants and many UX dead-ends, but mutation sync is still “best effort + console.warn” in the paths that matter most (resolve / reopen / Me too / Looks fixed).

## 2. Confirmed bugs

### P0 — Community “Looks fixed” can resolve locally without ever calling a server resolve RPC

| Field | Detail |
|--------|--------|
| **Severity** | P0 |
| **Evidence** | `confirmFix` (`js/app.js` ~22131–22268): on `Backend.enabled`, if `confirmFix` RPC returns `null` (network/error), still calls `finishResolve()` → `handleCommunityAutoResolve` → `applyResolution(..., 'community'|'citizen', ...)`. `Backend.updateReportResolution` (`js/app.js` ~15833–15857): for `by === 'community'` with no image, **no RPC runs** (only `set_resolution_image` when `imageUrl` is set). `pullAll` reconcile (`js/app.js` ~15550–15567): server row wins for known UUIDs → local `resolved` is overwritten by server `pending`. |
| **Impact** | User sees “fixed”, celebration/points may fire; after sync the pin reopens. Cross-device map stays wrong until someone succeeds on the RPC path. Owner points from `POINTS_REPORT_RESOLVED` are not clawed back. |
| **Fix direction** | On `confirm_fix` failure: do not call `finishResolve`; roll back local `fixConfirmations` / toast error. For community resolve without prior `confirm_fix` success, either call a dedicated resolve RPC or never mutate local status. Surface sync failure with the same toast pattern as `insertReport` (`toast.syncLocal`). |

### P0 — Stored XSS via unescaped report image URLs in `innerHTML`

| Field | Detail |
|--------|--------|
| **Severity** | P0 (security) |
| **Evidence** | `isSafeReportImage` (`js/app.js` ~2981–2986) allows any `^data:image/` string. Render sites interpolate raw URLs into HTML attributes without attribute escaping: `buildBeforeAfterSliderHtml` (~39711–39727), `buildSuccessStoryThumbHtml` (~39401–39424), share-win proof (~40825–40839), report cards (~45411–45445), admin queue thumbs (~46967–46969). Server `insert_report` (`supabase/schema.sql` ~2043–2105) stores `p_image` with only trim — no URL allowlist. A client can call the RPC (or fail Storage upload and fall back to data URL in `uploadReportImage` ~15381–15395) with e.g. `data:image/png," onerror="…`. |
| **Impact** | Any authenticated user who can place a crafted `image` / `resolution_image` can XSS every viewer who renders that report (map popup, Community wins, Profile cards, admin queue). |
| **Fix direction** | (1) `escapeAttr()` / never concatenate untrusted URLs into HTML — prefer `img.src = url` via DOM APIs. (2) Server-side: reject non-`https://…/storage/v1/object/public/report-photos/` values in `insert_report` / `set_resolution_image`. (3) Tighten `isSafeReportImage` to reject `"` / whitespace / non-http(s) beyond known prefixes. |

### P1 — Resolve / reopen / filing / cleanup sync failures are silent; local state + XP diverge

| Field | Detail |
|--------|--------|
| **Severity** | P1 |
| **Evidence** | `updateReportResolution`, `reopenReport`, `updateReportFiling`, `updateReportCleanup`, `confirmReport`, `flagReport` (`js/app.js` ~15857–15893): errors only `console.warn`. Contrast: `insertReport` / pledges show `toast.syncLocal` and set `syncPending`. `applyResolution` / `applyReopen` / `resolveOwnReport` mutate localStorage first, then fire-and-forget Backend. `pullAll` authoritative merge then drops divergent local status. |
| **Impact** | Self-resolve, reopen, BMC filing, cleanup can appear successful on-device and silently undo after sync. Civic points awarded in optimistic paths remain. Hard to debug in the field (no user-visible sync error). |
| **Fix direction** | Await RPC; on failure revert local mutation or mark `syncPending` + toast; retry in `pushLocalOwned`. Do not award resolve XP until server ack (or credit then debit on revert). |

### P1 — Me too corroboration is optimistic and fire-and-forget

| Field | Detail |
|--------|--------|
| **Severity** | P1 |
| **Evidence** | `confirmReport` (`js/app.js` ~21826–21891): increments local `confirmations`, awards `POINTS_ME_TOO`, then `Backend.confirmReport(reportId)` with no await / no rollback. Server RPC failure → `console.warn` only (~15885–15886). Next `pullAll` restores server count. |
| **Impact** | Inflated local Me-too counts and sticky points; leaderboard/XP skew; neighbours see wrong social proof until sync. |
| **Fix direction** | Await `confirm_report`; on error unclaim confirmation (helper already exists: `unclaimConfirmation`) and reverse points; toast on failure. |

### P1 — i18n: `toast.wardRequired` hardcodes Mumbai in hi / mr / gu

| Field | Detail |
|--------|--------|
| **Severity** | P1 (correctness for multi-city UX) |
| **Evidence** | EN (`js/app.js` ~5241): `'Pick a ward from the official {city} list.'`. HI/MR/GU (~7896, ~10549, ~13202): hardcoded Mumbai, no `{city}`. Call sites always `.replace('{city}', …)` (~2698, ~32076, ~43622) — no-op for those locales. |
| **Impact** | Pune/Thane users in HI/MR/GU are told to pick from Mumbai’s list — trust / onboarding friction. |
| **Fix direction** | Add `{city}` to all three locale strings (mirror EN). Optionally audit other keys that dropped `{city}` (e.g. `copy1916.gpsWarning` hi/mr/gu) even where `te()` currently forces EN for filing copy. |

### P2 — Civic XP / points cache is client-authoritative upward

| Field | Detail |
|--------|--------|
| **Severity** | P2 (integrity / abuse) |
| **Evidence** | `getTotalCivicXp` (`js/app.js` ~18856–18858) = report count × 50 + `localStorage` points cache. `sync_civic_xp` (`supabase/schema.sql` ~1647–1658) only allows upward moves ≤ +2000 per call. Console/`localStorage` edits ratchet server XP. |
| **Impact** | Leaderboard / certificates gameable; not a data-breach but undermines civic scoring trust. |
| **Fix direction** | Server-derived XP from audited events (report insert, confirm RPCs) or tighter caps + anomaly detection; treat client XP as display cache only. |

| Field | Detail |
|--------|--------|
| **Severity** | P2 |

### P2 — localStorage report photos unbounded until quota eviction

| Field | Detail |
|--------|--------|
| **Severity** | P2 (performance / reliability) |
| **Evidence** | Reports persist JPEG data URLs (`submitReport` ~36945–37004). Cap `maxReportsPerDevice: 500` (`js/config.js` / `SCALE_CFG`). `saveReports` quota loop trims non-own first (~14721–14748). |
| **Impact** | Heavy users hit `toast.storageFull` / eviction; janky JSON parse of multi‑MB blobs on every `loadReports` (microtask cache helps one tick only ~14680–14697). |
| **Fix direction** | Prefer Storage URLs only in local cache after upload; strip data URLs once `publicUrl` known; lower cap or separate photo store (IndexedDB). |

## 5. Recommended priority order for a fix pass

1. **P0 sync:** Stop local community auto-resolve when `confirm_fix` fails; never leave community resolve without a server write; user-visible error.  
2. **P0 XSS:** Attribute-escape / DOM-assign image URLs; server allowlist Storage URLs only.  
3. **P1 sync honesty:** Await + revert/toast for resolve, reopen, Me too (same pattern as report insert).  
4. **P1 i18n:** Fix `toast.wardRequired` (and scan sibling `{city}` regressions) in hi/mr/gu.  
5. **P2 polish:** Onboarding GPS-blocked copy; unify Backend offline sentinels; shrink local photo footprint; consider server-side XP.  
6. **Device QA:** WhatsApp prefill on production PWA; SW reload after deferred update; App Links.
